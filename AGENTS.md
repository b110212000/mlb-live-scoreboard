# MLB scoreboard maintenance

- React entry: src/main.jsx. App/navigation: src/App.jsx. Components: src/components.
- Engine compatibility modules in src/engine retain tested MLB/Web Push/detail renderer logic. React-managed DOM must not be mutated by engine code. Fixed detail hosts are intentionally memoized and remain mounted between page switches.
- Build using npm ci and npm run build; test using npm test (install Playwright Chromium first). Commit package-lock.json and generated root index.html, assets/app-<version>.js, its license file, and generated PNG icons, since GitHub Pages serves the root directly.
- Preserve the existing Worker and subscription format unless the task specifically calls for changing them.
- worker/ is deployed by Cloudflare Workers Builds, which runs `npm ci` in worker/. Keep worker/package-lock.json committed and regenerate it whenever worker/package.json changes (missing lockfile caused silent EUSAGE build failures from b774582 to 73e7065).
- A healthy /health does NOT prove a Worker deploy succeeded (the old deploy stays live). After pushing worker/ changes, verify the commit's "Workers Builds: mlb-score-notify" GitHub check-run is success, and that /api/push/public-key is unchanged.
- Subscriptions (v2.1.0+): the per-device DeviceRegistry Durable Object (worker/src/device-registry.js, keyed by the frontend deviceId) is the source of truth for a device's subscribed games, followed teams and notification prefs; it drives each game's GameMonitor via POST/DELETE /watch. The bell and the 訂閱管理 page use /api/devices/:deviceId/*. GameMonitor subscribers carry `prefs` (missing = all on, see worker/src/prefs.js); keep /api/watch working for old cached clients.
- Postponed/cancelled/removed games (codedGameState D/C/X, MLB reports Postponed as abstract "Final") are NOT final: never send 「比賽結束」 for them; use isCalledOffGame in worker/src/mlb.js.
- Only integrate official public APIs or properly licensed data. The owner rejected CPBL/NPB support because they lack public APIs (scraping or undocumented internal endpoints are not acceptable).
- MLB player data (people / stats / awards) is fetched per player only when the user opens that player (MLBAM terms allow individual, non-commercial, non-bulk use); never bulk-download every player's career. Match awards by award id (ALMVP, ALAS, ASMVP, MLBHOF, RETIREDUNI_<teamId>…, see src/players.js), not by name: minor-league, team and media awards reuse names such as "MVP", "Rookie of the Year" and "All-Star".
- Player biographies come from Wikipedia (src/wiki.js: Wikidata P3541 "MLB.com player ID", then name + birth date; zh-tw intro, English fallback). Wikipedia text is CC BY-SA 4.0: always keep the article link, "維基百科貢獻者" author credit and the license link next to it, and fetch per player on demand only.
- theme-light.css is GENERATED by npm run build (scripts/theme-light.mjs) from styles.css plus the hand-written src/theme-light.css; never edit it by hand and commit it with the build. Edit colours in styles.css; put light-only fixes in src/theme-light.css. Rules whose selector contains data-theme are not converted. tests/theme.cjs fails when theme-light.css is stale.
- styles.css keeps legacy global class names from the scoreboard (.team, .teams, .logo-shell…; on mobile .team becomes a column flexbox). Give new component classes a prefix (e.g. player-badge-team) instead of reusing generic names.
- i18n (v2.7.0+): every UI string goes through t('繁體中文原文') / tParts() from src/i18n.js; the Chinese text IS the dictionary key and the first argument must be a string literal (scripts/i18n-keys.mjs extracts keys). Add the English and Japanese translations to src/locales/en.js and ja.js in the same change; tests/i18n.cjs fails on missing or unused keys, mismatched {placeholders} or Han characters in English (`node scripts/i18n-keys.mjs --missing` lists gaps). Translate whole sentences with {placeholders}; never glue translated fragments (e.g. MLB 'Right' + '打'). Build label tables lazily (call t() at render time) so they follow language switches.
- Engine code gets t / lang / locale / teamName through createEngine; after a language switch store.setLang lets React re-render, then calls engine.relocalize() (src/engine/app.js relocalizeEngine) — re-render any new engine-written content there. Browser tests run with locale zh-TW (setup option `locale`); the language test asserts no Chinese remains on English pages.
- Push/calendar text is NOT in the frontend dictionaries: it lives in worker/src/messages.js (zh default; per-device `lang` stored in DeviceRegistry, sent to each GameMonitor via /watch, PUT /api/devices/:id/lang). Keep its team names identical to src/teams.js (tests/i18n.cjs compares them). Old subscribers without lang stay Chinese.
- The MLB live feed's game type is gameData.game.type (schedule objects use gameType); reading gd.game.gameType from a feed silently yields undefined.
- Follow user version rules: bug/UI patch +1, feature minor +1, major only explicitly requested.
- Bump package.json / footer / resource versions BEFORE running npm run build: the bundle is named after the package version, so building first rewrites the already-deployed assets/app-<old>.js in the working tree (restore it with git checkout before committing).
- npm run build regenerates assets/app-icon-*.png from app-icon.svg; output differs slightly between machines (anti-aliasing). If app-icon.svg did not change, git checkout the committed PNGs instead of committing the re-render.
- Before repository writes, read the latest main SHA. Never overwrite concurrent changes.
- Keep footer, package version, resource version references, README and icons in sync. version.json must be updated LAST in a separate commit after deployed assets have been verified.
- Do not describe browser simulations as physical iPhone/Web Push tests.
